# Stage 4 — Поддержка (тикеты), баны юзеров, "Предложить идею"

> Цель этапа: канал двусторонней коммуникации с клиентами через Telegram-группу с топиками. Один юзер = один топик. Юзер пишет в боте — админ отвечает в топике. Также реализуется бан/разбан с уведомлением.

---

## 1. Новые модели БД

### `tickets`
| Поле          | Тип          |                                          |
|---------------|--------------|------------------------------------------|
| id            | bigserial PK |                                          |
| code          | varchar(16) UNIQUE | формат `TCK-XXXXXX` (6 base36 chars) |
| user_id       | bigint FK    |                                          |
| kind          | varchar(16)  | `support`, `idea`                        |
| status        | varchar(16)  | `open`, `closed`                         |
| closed_by     | varchar(16) NULL | `user`, `admin`                      |
| closed_at     | timestamptz NULL |                                      |
| topic_thread_id | bigint NULL | message_thread_id в группе поддержки     |
| created_at    | timestamptz  |                                          |
| updated_at    | timestamptz  |                                          |

Индексы: UNIQUE(user_id) WHERE status='open' (партиальный индекс — гарантия "1 open на юзера"), `code`, `topic_thread_id`

### `ticket_messages`
| Поле          | Тип          |                                          |
|---------------|--------------|------------------------------------------|
| id            | bigserial PK |                                          |
| ticket_id     | bigint FK    |                                          |
| direction     | varchar(8)   | `from_user`, `from_admin`                |
| message_type  | varchar(16)  | `text`, `photo`, `sticker`               |
| text          | text NULL    |                                          |
| photo_file_id | varchar(255) NULL |                                     |
| sticker_file_id | varchar(255) NULL |                                   |
| tg_message_id | bigint NULL  | в группе или у юзера                     |
| created_at    | timestamptz  |                                          |

Индексы: `ticket_id`, `created_at`

### `support_topics`
Кэш привязки юзер → топик в группе.

| Поле          | Тип          |                                          |
|---------------|--------------|------------------------------------------|
| user_id       | bigint PK FK |                                          |
| topic_thread_id | bigint UNIQUE |                                       |
| topic_name    | varchar(255) | "TCK-XXXXX · {first_name}"               |
| created_at    | timestamptz  |                                          |
| updated_at    | timestamptz  |                                          |

> Один топик на юзера на всё время (по словам). При новом тикете — переиспользуем тот же топик; добавляем разделительное сообщение "Новый тикет TCK-YYYYY открыт".

## 2. Бот — флоу юзера

### Главное меню → "Поддержка"
- Если у юзера НЕТ открытого тикета:
  ```
  💬 Поддержка
  
  У вас нет активных тикетов.
  ```
  Кнопки: `[ Создать тикет ]`, `[ ← Назад ]`
- Если ЕСТЬ открытый тикет:
  ```
  💬 Тикет TCK-XXXXX открыт
  
  Напишите сообщение или прикрепите фото — мы получим его.
  ```
  Reply-клавиатура (постоянная, пока тикет открыт): `[ Закрыть тикет ]`.

### Создание тикета
- Кнопка "Создать тикет" → создаём `Ticket(status=open, kind=support)`, генерируем `code`.
- Если у юзера ещё нет `support_topic` → создаём топик в группе через `bot.create_forum_topic(group_id, name=...)`. Сохраняем `topic_thread_id`.
- Если есть — используем существующий, шлём в него разделитель: `<b>━━━ Новый тикет {code} ━━━</b>`.
- Юзеру: "Тикет TCK-XXXXX создан. Опишите вашу проблему." + reply-кнопка "Закрыть тикет".

### Сообщения от юзера
- В FSM-state юзера флаг `in_ticket=true` (или просто проверяем БД на наличие open ticket).
- Любое сообщение/фото в этом состоянии → форвардим в группу в формате:
  ```html
  <b>Тикет:</b> TCK-XXXXX
  <b>Пользователь:</b> {first_name}
  <b>Юзернейм:</b> @username (или "—")
  
  <b>Сообщение:</b>
  {text}
  ```
  Если фото — отправляем фото с тем же caption.
- Под сообщением — inline-кнопки:
  ```
  [ ❌ Заблокировать ]   [ ✅ Закрыть тикет ]
  ```
- Стикеры от юзера НЕ принимаем — отвечаем "Стикеры в тикетах не поддерживаются."
- Документы/видео — "Можно отправить только текст или фото."

### Закрытие юзером
- Reply-кнопка "Закрыть тикет" → подтверждение inline `[Да, закрыть] [Отмена]`.
- При закрытии:
  - Ticket status → closed, closed_by=user.
  - Юзеру: "Тикет TCK-XXXXX закрыт. Спасибо за обращение!" + убираем reply-клавиатуру.
  - В топик группы: `<b>Юзер закрыл тикет {code}</b>`.

### "Предложить идею"
- Та же механика, но `kind=idea`.
- В формате сообщения в группе: `<b>💡 Предложение идеи</b>` вместо "Тикет".
- Тоже не более 1 одновременно (или общая логика "1 ticket open" с любым kind? — **общая, упрощаем**).

## 3. Бот — флоу админа в группе

### Ответ админа
- Любое сообщение в топике от админа (любой пользователь группы с правом писать) → форвардим юзеру в боте:
  - текст → текст
  - фото → фото с подписью
  - стикер → стикер (юзеры могут получать стикеры от админа)
- В сообщении юзеру **НЕ показываем имя админа**, только сам контент с префиксом:
  ```html
  <b>Поддержка:</b> {text}
  ```
- Сохраняем в `ticket_messages(direction=from_admin)`.

### Inline-кнопки под сообщением юзера в группе
- **❌ Заблокировать**:
  - Запрашивает причину: бот в топике пишет "Введите причину блокировки одним сообщением (или /cancel)".
  - Админ пишет причину → юзер получает: "Вы заблокированы в боте. Причина: {reason}". `users.is_banned=true, banned_reason=...`. Все его последующие сообщения игнорируются.
  - В топик: "Юзер @username заблокирован: {reason}".
- **✅ Закрыть тикет**:
  - Ticket status → closed, closed_by=admin.
  - Юзеру: "Администрация закрыла тикет {code}".
  - В топик: "Тикет {code} закрыт администратором."

### Команды в топике (опционально)
- `/ban <reason>` — то же, что кнопка
- `/unban` — разбан
- `/close` — закрыть тикет
- `/info` — показать инфу о юзере (баланс, подписки)

## 4. Бан/разбан

### Бан
- `users.is_banned=true, banned_reason=...`
- Юзер получает уведомление с причиной (один раз при бане).
- Middleware бота: если `is_banned`, любое сообщение/команда → молчим (никаких ответов, чтобы не флудить).
- Исключение: команда `/start` тоже игнорируется (не показываем меню).
- Активные подписки **не отменяются** автоматически (если нужна деактивация — админ делает её отдельно).

### Разбан
- Только из админ-панели (Stage 5) или командой в группе `/unban` в топике юзера.
- `users.is_banned=false, banned_reason=null`.
- Юзер получает уведомление: "Вы разблокированы в боте."

## 5. Edge cases

| Кейс                                       | Поведение                                |
|--------------------------------------------|------------------------------------------|
| Юзер пишет в бота, не открыв тикет         | "Чтобы написать в поддержку, создайте тикет в разделе Поддержка." |
| Юзер открывает тикет повторно               | Ошибка "У вас уже есть открытый тикет {code}." |
| Юзер удалил топик (через клиент TG)        | Бот ловит ошибку при отправке, создаёт новый топик и обновляет support_topics |
| Бот вылетел из группы поддержки            | Все попытки отправки → лог critical + retry |
| Юзер заблокировал бота                     | TelegramBadRequest на отправку → ставим outbox в `failed`, в группе помечаем "юзер заблокировал бота" |
| Админ написал в топике без открытого тикета у юзера | Создаём "проактивный" тикет от имени админа? **Нет**, отвечаем в группе "У юзера нет открытого тикета. Сообщение не доставлено." |
| Закрытый тикет — нужно ли архивировать топик? | Нет, оставляем активным для следующих обращений того же юзера. |

## 6. Backend API эндпоинты Stage 4

```
# Bot
POST /api/bot/tickets/open                 -> создать тикет
POST /api/bot/tickets/{id}/close           -> закрыть от юзера
POST /api/bot/tickets/{id}/messages        -> сохранить сообщение (от юзера или админа)
GET  /api/bot/users/{tg_id}/active-ticket  -> {ticket} | null
POST /api/bot/users/{tg_id}/ban            -> бан
POST /api/bot/users/{tg_id}/unban          -> разбан
GET  /api/bot/support-topic/{user_id}      -> {topic_thread_id} | null
POST /api/bot/support-topic                -> сохранить новый thread_id
```

## 7. Безопасность / устойчивость

- Антифлуд для юзеров в тикетах: max 30 сообщений / минута, иначе "Слишком много сообщений, подождите."
- Лимит на размер фото — Telegram сам ограничивает, но дополнительно: одно сообщение = одно фото (альбомы не разбиваем).
- Все апдейты из группы поддержки фильтруются: только из `SUPPORT_GROUP_ID`, остальные — игнор.
- Логирование: каждое сообщение тикета → `tech_logs`.

## 8. Acceptance Criteria

- [ ] Юзер открывает тикет — в группе создаётся топик с правильным названием.
- [ ] Имя топика: `TCK-XXXXXX · {first_name}` (без юзернейма).
- [ ] Сообщение от юзера в боте → в топик с правильным форматом + inline-кнопки.
- [ ] Фото от юзера → пересылается в топик.
- [ ] Стикеры от юзера отвергаются.
- [ ] Сообщение от админа в топике → юзеру в бота с префиксом "Поддержка:".
- [ ] Стикеры от админа → юзеру.
- [ ] Кнопка "Заблокировать" работает, юзер получает уведомление с причиной, не может писать боту.
- [ ] Кнопка "Закрыть тикет" работает, юзер получает уведомление.
- [ ] Юзер может закрыть тикет своей кнопкой, в топик приходит уведомление.
- [ ] Нельзя открыть второй тикет, пока первый не закрыт.
- [ ] При повторном тикете того же юзера — переиспользуется его топик.
- [ ] "Предложить идею" работает по той же логике, что и тикет поддержки.
- [ ] Разбан юзера работает + уведомление.
- [ ] Антифлуд активирован.
