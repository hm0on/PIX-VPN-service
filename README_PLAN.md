# План работы — VPN PIX Bot

> Этот документ — оглавление плана. Каждый этап реализуется отдельно по команде "приступай к этапу N (файл stageN.md)".

---

## Принципы

1. **Микросервисная архитектура** — `backend` (FastAPI) + `bot` (aiogram 3) + `worker` (ARQ) + `admin` (React SPA). Бот не ходит в БД напрямую, только через Backend API.
2. **Стек**: Python 3.12, PostgreSQL 16, Redis 7, Docker, nginx + Let's Encrypt.
3. **Готовность к нагрузке с первого дня**: connection pooling, idempotency, outbox pattern, индексы, асинхронность везде.
4. **Безопасность**: проверка подписей webhook'ов, JWT для админки, ротация ключа, rate-limit, аудит-логи.
5. **Все суммы — в копейках**, никаких float.
6. **Все тексты бота — в БД** (HTML, редактируются из админки без редеплоя).
7. **HTML parse_mode** во всех сообщениях бота.

---

## Этапы

### [Stage 1 — Фундамент](./stage1.md)
Каркас всех сервисов, Docker Compose, БД (users/tariffs/texts/logs/admin_keys), бот с `/start` и главным меню, проверкой подписки на канал, авторизация админки по ключу из `.env`.

### [Stage 2 — Каталог, оплата, выдача ключей](./stage2.md)
Каталог тарифов, FSM покупки, интеграции Platega (СБП + крипта) + CryptoBot + Баланс, NorthLine API клиент, FREE-триал, профиль с подписками, идемпотентность, outbox.

### [Stage 3 — Промокоды, рефералка, продление, напоминания](./stage3.md)
Промокоды (на баланс / скидка) с лимитами, реферальная система (+100₽ / -10%), продление подписок, ARQ-задачи уведомлений за 3 дня и о истёкших.

### [Stage 4 — Поддержка (тикеты)](./stage4.md)
Тикеты support / idea, Telegram-группа с топиками, форвард сообщений в обе стороны, бан/разбан с уведомлением, антифлуд.

### [Stage 5 — Админ-панель](./stage5.md)
React SPA: дашборд с графиками, юзеры с детальными вкладками, подписки/ключи с деактивацией, CRUD тарифов и промокодов, рассылки с WYSIWYG и расписанием, редактор текстов бота, логи событий и технические.

## Использование

В любой момент можно сказать:

```
приступай к этапу 1 (файл stage1.md)
```

И я начну реализацию того этапа целиком. Между этапами обязательно **сначала** запускаем и проверяем предыдущий, потом переходим к следующему.

Если в процессе появятся уточнения — добавим их в соответствующий `stageN.md` перед началом реализации.
