# SECURITY — как заходить на сервер и что где включено

> Памятка для текущего сетапа сервера (pix-app.xyz).
> Без неё первый перезаход после смены ноутбука / переустановки ОС превратится в детектив.

## Главное в одну строку

```bash
ssh -p <SSH_PORT> <DEPLOY_USER>@<SERVER_HOST>
```

- Порт SSH и рабочий пользователь хранятся только во внешнем секретном конфиге.
- Рабочий пользователь имеет необходимые права для деплоя.
- Аутентификация **только по ssh-ключу**. Парольный вход выключен.
- Используется SSH-ключ из локального защищённого хранилища.

Если хочешь, добавь в `~/.ssh/config` локально:

```
Host pix
    HostName <SERVER_HOST>
    User <DEPLOY_USER>
    Port <SSH_PORT>
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

Тогда заход — просто `ssh pix`.

## Что лежит на сервере

- Проект находится в каталоге деплоя на сервере; точный путь хранится во внешней документации.
- Конфиг ssh — `/etc/ssh/sshd_config.d/99-hardening.conf` (drop-in, основной `sshd_config` не правил).
- Sudoers — `/etc/sudoers.d/90-deploy` (NOPASSWD).
- fail2ban — `/etc/fail2ban/jail.local`.

## Файрвол (ufw)

```
<SSH_PORT>/tcp  — ssh
80/tcp     — http (редиректит на https)
443/tcp    — https
```

Всё остальное — `deny incoming`. Postgres / Redis / backend / admin никуда не торчат.

Команды, которые пригодятся:

```bash
sudo ufw status verbose         # текущие правила
sudo ufw allow 1234/tcp         # открыть порт
sudo ufw delete allow 1234/tcp  # закрыть
sudo ufw disable                # выключить целиком (не делай на проде без причин)
```

## fail2ban — мягкие настройки

| Параметр | Значение | Комментарий |
|---|---|---|
| `maxretry` | 10 | 10 неудачных попыток за окно |
| `findtime` | 10m | окно учёта |
| `bantime`  | 30m | бан на полчаса (не сутки) |
| `ignoreip` | localhost + RFC1918 | свои сетки никогда не банятся |

Цель — поймать брутфорс (тысячи попыток в минуту), а не наказывать тебя за опечатку.

```bash
sudo fail2ban-client status sshd        # сколько забанено
sudo fail2ban-client unban <ip>         # снять бан вручную
sudo fail2ban-client set sshd unbanip <ip>
```

**Если ты случайно забанил сам себя**: зайди через панель хостера в консоль и выполни `sudo fail2ban-client unban <твой_ip>`. Или подожди 30 минут.

## Автообновления

- `unattended-upgrades` включён, ставит **только security-патчи** Debian.
- Не трогает версии docker-образов, не пересобирает приложение — это ручной процесс (`git pull && docker compose up -d --build`).
- Лог: `/var/log/unattended-upgrades/`.

## Если потерял доступ — план Б

Несколько уровней страховки, в порядке использования:

1. **Рабочий пользователь не пускает** → используй резервный административный доступ:

   ```bash
   ssh -p <SSH_PORT> root@<SERVER_HOST>
   ```

   Root тоже принимает тот же ключ (`PermitRootLogin prohibit-password`).

2. **Никакой ssh не пускает** (типа забанил себя через fail2ban) → подожди 30 минут, либо зайди через **VNC/панель хостера** (NodeHost даёт web-консоль) и сними бан:

   ```bash
   sudo fail2ban-client unban <твой_ip>
   ```

3. **Ключ потерян / ноут умер** → через web-консоль хостера логинься под root паролем (он только парольный там), затем добавь новый ключ:

   ```bash
   # Добавь новый ключ через защищённую консоль хостера.
   ```

4. **Ufw заблокировал всё, включая SSH** (не должно случиться, но мало ли) → web-консоль → `sudo ufw disable`.

## Что НЕ настроено (намеренно или по списку TODO)

- **Бэкапы Postgres** — пока нет, в следующей итерации (`pg_dump` по cron в `/opt/backups/`).
- **Off-site хранение** — ты сказал не нужно, бэкапы держим на самом сервере.
- **Rate-limit на админский логин в nginx** — отдельная задача, не критична пока админский slug секретный.
- **Внешний мониторинг** — нет UptimeRobot. Стоит подключить, чтобы узнавать о падениях не от пользователей.
- **Healthcheck для nginx** — отсутствует в docker-compose.

## Что менялось (changelog этой настройки)

## Сделай прямо сейчас (если ещё не)

1. **Смени root-пароль** (`passwd` под root) — старый засветился.
2. **При утечке токена** немедленно отзови его и заведи новый с минимальными правами.
3. **Сохрани приватный ключ** в надёжное зашифрованное хранилище.
